# 01. 工具定位與互動模式規格書

- **npm 套件名稱 (Package Name)**：`@loviusc/ai-meeting-notes`
- **CLI 指令名稱 (CLI Name)**：`meetnotes`
- **終端使用者互動型態 (Interaction Mode)**：`conversational`（安裝 `init` 後免指令純自然語言對話；日常整理會議、轉錄語者逐字稿、提煉摘要待辦與會後延伸討論皆完全透過自然語言對話完成，不需輸入任何 `CLI` 指令）
- **目標受眾**：需要定期召開週期性專案會議（如專案週會、產品檢討會、跨部門同步會議、客戶訪談）並希望將文字、錄音（Audio）、錄影（Video）自動轉化為結構化知識庫的專案經理（PM）、技術團隊主管、顧問與知識工作者。

## 核心痛點與價值主張

### 1. 核心痛點
- **多來源會議素材散落且缺乏語者脈絡**：會議來源包含現場錄音、線上會議錄影（`.mp4` / `.mkv`）、語音備忘錄（`.m4a` / `.mp3` / `.wav`）或零散文字筆記；一般轉錄工具常將所有人發言混成同一段文字，無法區分「誰說了什麼（Speaker Diarization）」，導致事後難以追溯責任歸屬與決策脈絡。
- **會議紀錄淪為靜態文字，缺乏待辦追蹤與會後討論機制**：傳統會議紀要寫完即封存，缺少將「逐字稿 -> 摘要與重點 -> 待辦事項（Action Items）與會後延伸討論」拆分的結構化設計，且無法針對特定議題直接與 AI 持續對話推演並同步回寫文件。
- **週期性會議缺乏主題歸檔與跨期連貫性**：同一專案（如「A 專案」）每週或定期開會時，若未按「專案主題資料夾 -> 日期場次資料夾」統一歸檔，前次會議未完成的待辦事項與歷史決議極易在下一次會議中被遺忘。

### 2. 核心價值主張
- **免指令純自然語言對話體驗 (`conversational` Mode)**：終端使用者初始化工作區後，日常操作**零 CLI 指令負擔**。只需直接對 AI 丟入影音檔、初稿字幕或文字筆記並用日常語言說出需求（例如：「這是今天 A 專案的會議錄音，與會者有陳總與林工，請幫我整理」），AI 即自動建立專案與日期資料夾並產出完整文件。
- **「非 LLM 專用轉錄 + AI 語意後處理」二階段解耦架構 (`ASR First, AI Second`)**：
  由於大型 `.mp3` / `.mp4` 影音檔（常達數十至數百 MB、時長 30~120 分鐘）不適合也不應完全依賴對話型 LLM 直接硬讀音訊（易受 Context Window 限制、耗費大量 Token 且長音訊易漏字），本工具將「語音轉文字」與「AI 整理」明確解耦為兩階段：
  1. **第一階段：非對話 AI 的專用轉錄層（0-LLM-Token 取得含時間戳與語者代號初稿，支援 5 大核心語系、中英夾雜與 99+ 多國語言音訊）**：
     - **支援語音語言範圍**：原生最佳化 **繁體中文（含台灣常見中英夾雜 Code-Switching）、簡體中文、英文（`en`）、日文（`ja`）、韓文（`ko`）** 五大主力語言；同時依托 `Whisper` / `WhisperX` 與專用 `STT` 模型底層能力，可辨識 **粵語（`yue`）、德文、法文、西文、越南文、泰文等 99+ 種語言音訊**（支援「外語會議錄音 -> 保留原文或雙語 `01-transcript.md` + 自動產出 `zh-TW` 繁體中文 `02-summary.md` 與 `03-todos-and-discussion.md`」跨語系會議整理）。
     - **途徑 A（外部現成轉錄檔 + 原始影音雙匯入）**：直接匯入會議軟體（Teams / Zoom / Google Meet）、錄音筆（如 Plaud）或本地轉錄軟體（如 MacWhisper / 剪映）已產出的 `.srt` / `.vtt` / `.txt` 字幕初稿，並將原始 `.mp3` / `.mp4` 一併歸檔至 `media/`。
     - **途徑 B（本機離線 ASR + Diarization 引擎自動執行）**：當只提供 `.mp3` / `.mp4` 時，由本機工具鏈（如 `ffmpeg` + `WhisperX` / `faster-whisper` / `mlx-whisper` + `pyannote.audio`）在背景直接將影音轉為帶 `[HH:MM:SS]` 與 `SPEAKER_00` / `SPEAKER_01` 的文字初稿，完全不消耗 LLM Token。
     - **途徑 C（專用 Speech-to-Text API 轉錄）**：或透過專用語音 `API`（如 `AssemblyAI`、`Deepgram`、`OpenAI Whisper API`、`Google Cloud STT`）快速取得高精準度語者分離初稿。
  2. **第二階段：AI Agent 語意介入層（語者實名對齊 + 專有名詞校正 + 三檔提煉 + 零幻覺與三級可控風險主動揭露）**：
     - AI 介入處理第一階段產出的「粗糙文字初稿」，依據專案上下文與出席名單，將 `SPEAKER_00` / `SPEAKER_01` 映射為真實與會者姓名、修正技術專有名詞同音錯字並格式化為 `01-transcript.md`，再進一步提煉 `02-summary.md` 與 `03-todos-and-discussion.md`。
     - **零幻覺、可控風險分級與高不確定性主動說明 (`Zero-Hallucination & Controllable Risk Matrix`)**：建立嚴格的三級風險與確定性控管（`🟢 已驗證事實`：100% 具逐字稿行號與時間戳依據；`🟡 可控推論風險`：依上下文合理推斷但主動標明推論依據與風險；`🔴 高不確定性需人為介入`：音訊模糊、語者不明、關鍵數據或決議未定案時，嚴禁腦補猜測，強制標示 `⚠️ [需人為確認]` 並附上原始影音時間戳記 `[HH:MM:SS]` 與風險說明，交由使用者裁示）。
     - **跨場次歷史會議衝突偵測與主動提醒 (`Cross-Meeting Conflict Detection & Alert`)**：由於週期性會議皆歸檔於同一專案目錄下，AI 在整理新會議時會自動比對該專案過往會議的決議、時程、預算數據與待辦負責人；一旦發現**本次會議內容與先前會議紀錄存在矛盾或衝突**（如決議翻盤、時程/數字不一致、負責人變動），會主動列出「本次說法 vs. 前次紀錄（含日期與行號引用）」提醒使用者確認是「正式變更」或「與會者口誤」。
- **極致省 Token 的三層成本控管架構 (`Token-Efficiency & Cost Control Architecture`)**：
  1. **逐字稿實名化採用「AI 產出映射表 + 0-Token 批次替換」**：面對動輒 1~2 萬字的長會議初稿，禁止 AI 重新逐字 Output 整篇逐字稿（避免昂貴的 Output Token 消耗），改由 AI 判讀後輸出精簡的「語者代號與專有名詞校正映射表」，透過本機批次替換生成 `01-transcript.md`，節省 90% 以上 Output Token。
  2. **跨期衝突比對採用「`index.md` 滾動基準快照」**：在 `meetings/<專案>/index.md` 維護精簡的「當前有效決議、時程預算基準與未結案待辦快照（約 500~1,000 Tokens）」；新會議比對衝突時僅需讀取 `index.md` 與上一場會議摘要，**嚴禁載入歷次會議的完整 `01-transcript.md`**，使跨期比對的 Token 消耗維持固定常數（$O(1)$），不隨會議場次增加而暴增。
  3. **會後討論與衍生文件採用「`#Lx-Ly` 局部按需讀取 (`Lazy Line-Range Loading`)」**：會後討論與套用範本產出文件時，預設僅載入 `02-summary.md` 與 `03-todos-and-discussion.md`；需查證原話時僅依 `#Lx-Ly` 讀取 `01-transcript.md` 對應的數十行片段，不重複載入整份逐字稿。
- **會後衍生業務文件產出與範本套用引擎 (`Post-Meeting Deliverable & Template Engine`)**：
  - 除了標準三份會議紀錄（`01`~`03`）外，支援於會後直接根據會議結論與討論內容**衍生產出各類後續業務文件**（如：會後確認信 Follow-up Email、需求規格書 PRD、變更申請單、報價提案草稿、事故檢討報告等），並統一存放於當次會議目錄下的 `deliverables/` 子目錄。
  - **支援「有範本套用」與「無範本起草」雙模式**：使用者可預先於專案放置自訂範本（如 `meetings/<專案主題>/templates/` 或臨時提供範本），AI 會將會議決議精準填入範本；**若範本中某欄位在會議中未曾提及，AI 嚴格遵守零幻覺鐵律，絕不自行編造，而是標註 `⚠️ [會議未提及 - 需人工補填]` 並主動說明缺漏項**。
- **三檔分離標準化產出與會後互動討論**：每次會議固定於日期資料夾內產出三份職責分明的文件：
  - `01-transcript.md`：包含時間戳記與發言人姓名的完整語者分離逐字稿。
  - `02-summary.md`：高階主管摘要、核心討論重點與正式決議（強制附帶逐字稿行號引用以杜絕 AI 幻覺）。
  - `03-todos-and-discussion.md`：結構化待辦清單（含負責人、期限、狀態、跨期追蹤）與**會後互動討論區**，支援使用者隨時與 AI 針對會議議題深入討論並動態更新結論。
- **週期性專案與日期雙層歸檔架構（原始影音隨會議目錄封裝 + 極簡純淨目錄）**：自動以 `meetings/<專案主題>/<YYYY-MM-DD_會議主題>/` 組織所有會議資產。由於原始錄音與錄影檔是極為重要的會議依據，**所有原始多媒體檔案（Audio / Video）皆強制保存在該場會議的日期目錄內**（與 `01-transcript.md`、`02-summary.md`、`03-todos-and-discussion.md` 放在一起，並在逐字稿頂部記錄媒體檔案相對路徑、時長與 `SHA-256` 校驗碼，確保完整可溯源）；同時針對大檔案提供 `.gitignore` / `Git LFS` 友善保護，讓本機會議目錄永久完整保留重要影音檔且不卡死 `Git`。工作區與會議資料夾內**嚴禁產生 `skills/`、`rules/`、`AGENTS.md` 等多餘外露檔案**（預設強制啟用 `hideSkillsRules: true`）。
