# 02. 業務流程與產出文件結構設計

## 自然語言對話觸發或 CLI 流程
- **觸發方式**：採用 **`conversational`（免指令純自然語言對話）** 觸發。使用者日常無須輸入任何 `CLI` 指令，也不必手動建立深層資料夾，支援以下 **3 種直覺的新建會議與匯入媒體方式**：
  - **方式 A（對話框直接拖曳/給路徑，AI 全自動建檔歸位）**：使用者直接在 AI 對話視窗拖入桌面/下載區的錄音、錄影檔（或貼上文字/檔案路徑），並說出如*「這是今天 A 專案的週會錄音，幫我整理」*。AI 會自動建立 `meetings/A專案/YYYY-MM-DD_週會/media/`，並自動將該影音檔複製/搬移歸檔至 `media/` 中，隨即產出三份會議文件。
  - **方式 B（檔案總管隨手丟入專案目錄，AI 自動偵測歸位）**：使用者在 Finder / 檔案總管直接把影音檔丟進工作區根目錄或 `meetings/A專案/` 下（不需手動建日期與 `media/` 資料夾），再對 AI 說*「幫我把剛放進來的錄影檔整理成 A 專案今天的會議」*。AI 會自動掃描新放入的媒體檔、建立日期目錄並將檔案移入 `media/` 後開始轉錄整理。
  - **方式 C（說「新增會議」啟動互動引導）**：使用者只需說*「我要新增會議」*，AI 會主動列出目前 `meetings/` 下已有的專案供選擇（或新建專案）、確認日期與會議名稱，先幫使用者建好 `meetings/<專案>/<日期>/media/` 空資料夾，提示使用者將影音檔放入或貼上文字後即刻處理。
- **核心步驟**：
  1. **專案與日期資料夾定位與重要影音同目錄歸檔（Project & Date Folder Routing & Media Co-location）**：
     - AI 解析使用者輸入的「專案/主題名稱」（例如：`A專案`）與「會議日期」（未指定時預設採用當日 `YYYY-MM-DD`）。
     - 自動檢查並建立專案主題資料夾 `meetings/<專案名稱>/` 與該次會議專屬日期資料夾 `meetings/<專案名稱>/<YYYY-MM-DD>_<會議名稱>/`。
     - **重要多媒體檔案隨會議目錄完整保存**：因為錄音、錄影檔是關鍵的原始憑證，所有該場會議的多媒體檔案皆直接存放於該次會議目錄下（`meetings/<專案名稱>/<YYYY-MM-DD>_<會議名稱>/media/` 或該日期目錄內）。若使用者從桌面或下載區指定外部影音檔，AI 會自動將其搬移或複製進該場會議目錄中統一封裝保存，絕不刪除原始影音。
     - 若該專案已有歷史會議紀錄，自動讀取 `meetings/<專案名稱>/index.md` 與前次會議的 `03-todos-and-discussion.md`，載入與會者名單習慣與前期未完成待辦事項。
  2. **二階段媒體轉錄與語者分離（Stage 1 非 AI 專用轉錄 -> Stage 2 AI 語意校正）**：
     - **Stage 1（非 LLM 介入：取得粗略語者逐字稿）**：針對 `.mp3`、`.m4a`、`.wav`、`.mp4` 等多媒體檔，不讓對話 AI 直接硬吃龐大音訊，而是依序優先採用：
       1. **已有現成字幕/初稿（零等待）**：若使用者同時提供了會議軟體或錄音工具匯出的 `.srt`、`.vtt`、`.txt` 初稿與 `.mp3`/`.mp4` 原始檔，直接將影音歸入 `media/`，並讀取文字初稿。
       2. **呼叫本機 ASR 或專用 STT 工具（零 LLM Token）**：若僅提供 `.mp3`/`.mp4`，由系統檢查並呼叫本機安裝的語音轉錄指令（如 `whisperx`、`mlx_whisper`、`whisper` 或設定之專用 `STT API`）將 `media/` 內的影音轉出含時間戳記與 `SPEAKER_00` / `SPEAKER_01` 的原始文字檔（存放於 `media/` 旁作為轉錄中繼檔）。
     - **Stage 2（AI Agent 介入：語者實名映射與省 Token 批次校正）**：AI 讀取 Stage 1 產出的粗略文字稿，結合專案 `index.md` 的固定成員名單與上下文語意，推斷各語者代號對應的真實姓名（例如：`SPEAKER_00 -> 王經理 (PM)`、`SPEAKER_01 -> 李工程師 (Backend)`）與同音專有名詞校正表。**為大幅節省 Output Token，當逐字稿篇幅較長時，優先透過映射字典與本機字串批次替換寫入標準化的 `01-transcript.md`**，僅針對高不確定性段落插入 `⚠️ [需人為確認]` 標記，避免讓 LLM 逐字重寫數萬字長文。
  3. **三檔分離提煉與跨期脈絡串聯（3-File Structured Synthesis）**：
     - **第一步：產出語者分離逐字稿 (`01-transcript.md`)**：記錄會議基本資訊（日期、時間、專案、與會者名單、原始檔案路徑）與逐行編號的語者對話內容（格式：`[HH:MM:SS] **發言人**：發言內容`）。
     - **第二步：提煉會議摘要與重點決議 (`02-summary.md`)**：根據 `01-transcript.md`，提煉出「會議目的與執行摘要（Executive Summary）」、「分議題核心討論重點（Key Points）」、「正式決議事項（Decisions）」，且每一條重點與決議皆標註對應 `01-transcript.md` 的真實行號範圍（`#Lx-Ly`），確保 100% 忠於原意。
     - **第三步：整理待辦事項與開啟會後討論 (`03-todos-and-discussion.md`)**：從逐字稿中萃取所有明確或隱含的行動項目（Action Items），整理為含「編號、待辦事項、負責人（Owner）、截止日期（Due Date）、狀態、逐字稿來源行號」的結構化表格；同時比對前次會議未完成待辦的進度，並在文件下方建立「會後延伸討論與決策補充區（Post-Meeting Discussion）」。
  4. **完稿強制品質檢核規則（Post-Generation Quality & Integrity Inspection Rule）**：
     - 當 `01-transcript.md`、`02-summary.md`、`03-todos-and-discussion.md` 與專案 `index.md` 建立或更新完成後，系統強制觸發**「五維度完稿檢核規則（Post-Meeting Document Verification Rule）」**：
       1. **目錄純淨與三檔齊全檢核**：確認日期資料夾內三份文件齊全、重要影音檔已歸位至 `media/`，且外層無散落未歸檔影音或外露系統檔。
       2. **語者分離與媒體連結檢核**：確認 `01-transcript.md` 頂部 `./media/` 連結有效，且每段對話皆有時間戳記與明確發言人標籤（若有未識別姓名的 `Speaker A/B` 則列入待確認清單）。
       3. **逐字稿行號防幻覺溯源檢核**：逐條核對 `02-summary.md` 的重點/決議與 `03-todos-and-discussion.md` 的待辦事項，確認其引用的 `./01-transcript.md#Lx-Ly` 行號真實存在且語意吻合。
       4. **待辦事項完整性與跨期同步檢核**：確認每項待辦皆有負責人與期限（未定者標註 `TBD`），且已同步更新至 `meetings/<專案名稱>/index.md` 跨期追蹤表。
       5. **跨場次歷史衝突比對檢核 (`Cross-Meeting Conflict Check`)**：自動將本次會議的決議、時程、關鍵數據與待辦指派，與同專案前幾次會議的 `02-summary.md`、`03-todos-and-discussion.md` 及專案 `index.md` 進行交叉比對；若發現前後不一致或衝突，強制於文件中標註 `⚡ [與前次會議衝突]`（並列出前次會議日期與行號對照）。
       6. **高不確定性主動攔截與人為介入檢核 (`Human-in-the-Loop Check`)**：掃描轉錄與提煉過程中是否存在「無法確定誰說的話」、「聽不清楚的關鍵金額/日期/專有名詞」或「未明確拍板的爭議決議」；若有，必須確認已標記 `⚠️ [需人為確認]` 與對應音檔時間戳記 `[HH:MM:SS]`，絕不強行猜測。
       7. **零佔位符與語系純粹性檢核**：確認無任何殘留的雙大括號模板佔位符，且符合 `zh-TW` 語言規範。
     - 檢核通過後，AI 於對話中向使用者回報檢核結果摘要；**若存在任何高不確定性項目或與之前會議衝突之處，必須主動在對話中列出「🚨 需人為介入確認清單」與「⚡ 跨期會議衝突提醒（對比本次 vs. 前次紀錄）」，請求使用者人為確認**。
  5. **會後雙向互動討論與專案索引同步（Interactive Follow-up & Project Index Sync）**：
     - 使用者隨時可用自然語言針對會議內容提問或延伸討論（例如：「針對第二點決議，如果時程提前一週會有什麼風險？幫我補充到討論區並新增一筆給小張的待辦」）。
     - AI 回應分析後，自動將討論結論與新增/修改的待辦回寫至 `03-todos-and-discussion.md`（必要時同步更新 `02-summary.md` 與 `meetings/<專案名稱>/index.md`），並再次執行上述完稿檢核規則確保一致性。
  6. **會後衍生文件產出與範本套用（Post-Meeting Deliverable Generation with Optional Templates）**：
     - 當使用者於會後需要產出特定交付文件時，直接以自然語言告知（例如：「用我們的規格範本，根據今天會議決議產出一份 API 變更單」或「幫我根據今天會議寫一封給客戶的會後確認信」）。
     - **有範本模式（Template-Driven）**：AI 讀取 `meetings/<專案名稱>/templates/` 下的指定範本（或使用者當下提供的範本檔案），將 `01-transcript.md`、`02-summary.md`、`03-todos-and-discussion.md` 中已確認的事實填入對應欄位並附上 `#Lx-Ly` 溯源；對於範本要求但會議中未討論到的欄位，強制標記為 `⚠️ [會議未提及 - 需人工補填]` 並在對話中主動列出缺漏欄位與風險說明。
     - **無範本模式（Ad-Hoc Structured Drafting）**：若無現成範本，AI 依據該類商務/技術文件最佳結構起草，所有數據與承諾皆嚴格綁定會議逐字稿依據。
     - 產出之衍生文件統一儲存於該場會議目錄下的 `meetings/<專案名稱>/<YYYY-MM-DD>_<會議名稱>/deliverables/`（或依使用者指定命名），並自動執行完稿檢核規則。

## 產出文件清單（極簡純淨目錄結構）

工作區與會議資料夾嚴格保持純淨，**不產生 `skills/`、`rules/` 等任何外露系統資料夾或多餘檔案**。每次會議均依「專案主題 -> 日期」階層存放，完整目錄與產出文件結構如下：

- `meetings/<專案主題名稱>/index.md`：**專案會議總覽與跨期追蹤表**（記錄該專案背景、固定與會成員角色表、歷次會議日期連結清單、跨場次未完成待辦事項匯總）。
- `meetings/<專案主題名稱>/templates/`：**（選用）專案專屬會後文件範本庫**（可存放該專案常用的會後產出範本，如變更單範本、週報範本、客戶確認信範本、PRD 範本等）。
- `meetings/<專案主題名稱>/<YYYY-MM-DD>_<會議主題>/media/`：**當次會議重要多媒體原始檔存放區**（直接將該場會議的錄音檔 `.mp3`/`.m4a`/`.wav`、錄影檔 `.mp4`/`.mov`/`.mkv` 或原始素材保存在該場會議目錄內，確保會議紀錄與原始影音證據永遠封裝在同一處，隨專案資料夾一併備份與查閱）。
- `meetings/<專案主題名稱>/<YYYY-MM-DD>_<會議主題>/01-transcript.md`：**語者分離逐字稿**（頂部記錄同目錄下 `media/` 原始影音檔之相對連結、檔案大小、時長與 `SHA-256` 校驗值；內文含語者身分對照表、帶時間戳記 `[HH:MM:SS]` 與明確發言人標籤的完整逐字稿）。
- `meetings/<專案主題名稱>/<YYYY-MM-DD>_<會議主題>/02-summary.md`：**會議摘要與核心重點文件**（含一句話總結、核心討論重點、關鍵爭議與共識、正式決議清單，所有要點均附帶指向 `01-transcript.md#Lx-Ly` 的來源引用與三級風險/確定性標記）。
- `meetings/<專案主題名稱>/<YYYY-MM-DD>_<會議主題>/03-todos-and-discussion.md`：**待辦事項與會後延伸討論文件**（含前期未完成待辦追蹤表、本次新增待辦事項表、🚨 需人為介入與風險確認清單，以及可持續與 AI 對話累加的「會後延伸討論紀錄區」）。
- `meetings/<專案主題名稱>/<YYYY-MM-DD>_<會議主題>/deliverables/`：**（按需產出）會後衍生業務文件存放區**（存放根據該場會議決議與範本自動產出的後續文件，如 `follow-up-email.md`、`change-request.md`、`prd-draft.md` 等，每份文件皆具備對 `01-transcript.md` 的零幻覺溯源與缺漏欄位標示）。
